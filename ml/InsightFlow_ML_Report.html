Prétraitement des Données — preprocess.py
1. Nettoyage du texte
  • ✂️ Suppression URLs & emails
  • ✂️ Suppression tokens base64
  • ✂️ Signatures & reply chains
  • ✂️ Caractères spéciaux (accents FR conservés)
  • ✂️ Normalisation des espaces
2. Filtrage qualité
  • 📏 Longueur min : 5 mots
  • 📏 Longueur max : 300 mots (troncature)
  • 🔍 Déduplication (150 premiers chars)
  • ⚠️ Ratio déséquilibre max : 2.0×
3. Équilibrage & Split
  • ⬆️ Oversample (défaut) : augmenter classes minoritaires
  • ⬇️ Undersample : réduire classe majoritaire
  • ⚖️ None : class weights pendant training
  • 🎯 Split stratifié : 70 / 15 / 15
Formule — Class Weighting (déséquilibre)
weight[i] = total_samples / (num_classes × count[i])
Appliqué via WeightedTrainer avec CrossEntropyLoss pondéré. Gère le déséquilibre sans sur-échantillonnage systématique.

Calibration — Temperature Scaling
✅ La calibration réduit l'ECE (Expected Calibration Error) de 0.18 → 0.04, soit une amélioration de 77.8%. Un modèle bien calibré produit des scores de confiance fiables pour la prise de décision.
Processus de calibration — calibrate_emotion.py

Étape 1 — Split validation

Inférence sur 20% du validation set → logits + labels

Étape 2 — ECE avant calibration

Compute ECE = 0.18 (modèle sur-confiant)

Étape 3 — Optimisation température T

Minimiser NLL · Bornes : T ∈ [0.1, 5.0] · scipy.optimize

Étape 4 — Application

softmax(logits / T) avec T = 1.63

Étape 5 — ECE après calibration

ECE = 0.04 · Amélioration = 77.8%

Sauvegarde

ml/models/insightflow-emotion-xlm-v1/temperature.json

ECE avant vs après calibration

Paramètres calibration — temperature.json
{ "temperature": 1.63, "ece_before": 0.18, "ece_after": 0.04, "improvement": 77.8, "method": "temperature_scaling", "reference": "Guo et al. 2017" }

T > 1 → modèle était sur-confiant (softmax trop "peaked") · Appliqué automatiquement par EmotionProcessor si temperature.json existe

Pipeline Continuous Learning — continuous_learning.py

1. Extraction corrections PostgreSQL

Table human_corrections · Filtre: non utilisées, texte > 20 chars, labels valides

2. Construction dataset Experience Replay

Nouvelles corrections + 30% données originales → évite l'oubli catastrophique

3. Fine-tuning Challenger

3 epochs · LR=1e-5 · batch=8 · mêmes args que initial

4. Évaluation Champion vs Challenger

Sur même val set → challenger promu si F1 ≥ F1 champion

5. Tracking MLflow

Experiment: insightflow-{task} · Métriques, params, artifacts, aliases

6. Marquer corrections utilisées

PostgreSQL: used_in_training=TRUE, training_run_id={uuid}

7. Rapport JSON

ml/training_reports/cl-{task}-{ts}-{uuid}.json
